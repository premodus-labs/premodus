Technology is often judged at the moment it is launched. The harder question is whether it will still be useful when the team changes, the network is unreliable, or the original funding has ended.

## Start with the actual work

The people using a system already have a way of getting work done. It may be slow, paper-heavy, or held together by phone calls, but it contains knowledge about constraints. Good software pays attention to that knowledge before it starts redesigning the process.

- Observe the work where it happens.
- Make the first useful version small enough to learn from.
- Treat maintenance as part of the product, not a later phase.

## Capability is a feature

A system is more valuable when its owner can understand, operate, and improve it. Clear documentation, sensible defaults, and straightforward handover are not extras. They are how technology remains useful after its builders step away.
